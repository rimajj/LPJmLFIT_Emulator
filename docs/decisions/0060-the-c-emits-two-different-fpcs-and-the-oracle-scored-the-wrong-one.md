# ADR 0060 — the C emits TWO different FPCs, the F-side oracle scored the wrong one, and F over-predicts crown cover where it was published as under-predicting

* **Status:** Accepted
* **Date:** 2026-08-06
* **Line:** M (multi-cell coupled S+F+E) · ADR block 0050–0069 (tier 1)
* **Decides:** the F-vs-C foliage-projective-cover comparison is scored against the C's **`a_fpc`**
  output (`FPC`, the patch-mean sum of individual crown covers), **not** `a_fpc_stand` (`FPC_STAND`, a
  leaf-area Beer–Lambert form). Both are now emitted as separate committed columns
  (`fpc_tree_crown` / `fpc_tree`) so the substitution cannot recur silently.
* **Withdraws:** **ADR 0053 finding 4** — *"F under-predicts tree FPC in all five cells (0.31–0.72×)"*,
  described there as *"the most robust structural finding in the set"*. It is a reference-basis artifact.
  On the comparable output F **over**-predicts in four of five cells. Consequently
  `lines/M/STATE.md` NEXT item 4(d) is withdrawn as stated.
* **Re-scopes:** ADR 0105 §5 (line S's hand-over of the coupled count residual to F's canopy). The
  *attribution* survives — F's canopy does diverge from the C's — but its supporting FPC numbers were read
  off the same wrong column and their per-cell magnitudes change.
* **Related:** ADR 0053 (the oracle basis this corrects, whose other three basis fixes stand), ADR 0057
  (the 25-patch ensemble, used here), ADR 0059 (the water-scalar default, active in these runs),
  ADR 0105 (line S's attribution), CLAUDE.md §3 (the `ind` writer's 5 m height filter),
  `residual-diagnosis` §3f (*same NAME ≠ same QUANTITY*), guardrail 4.
* **Evidence:** jobs **1718928 / 1718932 / 1718979** — `scripts/biome_fdiff_oracle_probe.jl`, 5 biome cells,
  25-patch ensemble, historic 2010–2019, `slow = nothing`, `wscal_leafon = true` — plus job **1718987**
  (`scripts/biome_slow_oracle_probe.jl`, the coupled arm) as an independent cross-check of the C-side crown
  figures through a second reader (§4). Committed tables regenerated by
  `scripts/extract_biome_fdiff_oracle.py`; every pre-existing column is byte-identical (verified row-by-row)
  — the change is purely additive.

## 1. The two outputs, and why they are not the same variable

`annual_natural.c` writes both, in the same loop, from the same individuals:

| output | file | expression | what it is |
|---|---|---|---|
| `FPC` | `a_fpc.nc` | `:209` `+= pft->fpc/npatch`, with `pft->fpc = CA·nind·(1−exp(−k·LAI_ind))` (`fpc_tree.c:28`) | patch-mean **sum of individual crown covers**. In `individual = true` each `Pft` *is* one individual, so this is a sum over stems. Not bounded by 1. |
| `FPC_STAND` | `a_fpc_stand.nc` | `:218` accumulates per-PFT **leaf area** `Σ leaf_c·sla/npatch`, then `:248` applies `1 − exp(−k_pft·(Σleafarea/patcharea))` | one Beer–Lambert saturation of the PFT's total leaf area **spread over the whole patch**. The C's own comment: *"effective FPC as if tree crowns where spread over the whole forest patch"*. Bounded in [0,1) per PFT. |

They are different functional forms of different arguments. Measured on these five cells over 2010–2019,
`crown / BLstand` = **0.44 – 0.67** — a factor of 1.5–2.3, larger than any F-side bias being chased.

**F_diff implements the crown form.** `src/allometry.jl::fpc` is
`FPC = CA·N·(1 − exp(−k·LAI))` with a source comment naming `fpc_tree.c:28`, and
`FDiff._treepools_fpc` / `stand_structure_tof(...).fpc` sum it over the roster. So `a_fpc` is the
comparable output and `a_fpc_stand` is not.

## 2. How the wrong one got scored

The extractor's own docstring said FPC was *"SPLITTABLE, per-PFT bands"* and picked `a_fpc_stand`; the
probe's basis header then asserted *"Same quantity (`fpc_tree.c:28`), tree-only on both sides. **CLEAN.**"*
— citing the correct C line for a file that does not implement it. Both files have identical band layouts
(band 0 natural fraction, 1..7 trees, 8..10 grass) and plausible values in [0,1], so nothing looked wrong.

This is `residual-diagnosis` §3f exactly, and the specific trap it warns about: the note *"the C's `swc` is
not the model's `w`"* was already in CLAUDE.md for soil water, and the same shape recurred one output
directory away. The generalisable tell is that **`a_fpc.nc` was sitting unread in every one of the five run
directories** — a second file with almost the same name is a prompt to read both writers, not to pick the
one whose name matches the variable.

## 3. What the corrected comparison says

`scripts/biome_fdiff_oracle_probe.jl` PART 3, 10-yr means, 25-patch ensemble:

| cell | F | C crown (`a_fpc`) | **ratio** | C BL-stand | old ratio (withdrawn) |
|---|---|---|---|---|---|
| `boreal_siberia` | 0.370 | 0.281 | **1.32** | 0.561 | 0.66 |
| `temperate_hainich` | 0.625 | 0.529 | **1.18** | 0.871 | 0.72 |
| `mediterranean_iberia` | 0.408 | 0.277 | **1.47** | 0.626 | 0.65 |
| `semiarid_sahel` | 0.161 | 0.301 | **0.54** | 0.526 | 0.31 |
| `tropical_amazon` | 0.681 | 0.648 | **1.05** | 0.971 | 0.70 |

**The sign flips in four of five cells.** "F under-predicts tree FPC in all five cells" becomes *F
over-predicts crown cover in four cells by 1.05–1.47× and under-predicts in one — the Sahel, at 0.54×.*

Two consequences worth stating plainly:

- **The withdrawn finding pointed the wrong way.** ADR 0053 read the deficit as *"fewer/less extensive
  crowns carrying comparable or greater leaf area"* and treated it as the set's most robust structural
  result. The excess crown cover in four cells is the opposite defect and needs a different fix.
- **The Sahel is the one cell where the old verdict's direction survives**, and it is the same cell
  ADR 0052 (root zone too dry), ADR 0053 (monotone canopy dieback) and ADR 0055 (no recovery from a pool
  perturbation, τ 602 yr) already isolate. Fourth independent symptom, same cell.

### The 5 m truncation, which biases F's ratio DOWN

F's stand is built from `M_individuals_<name>_2010.csv`, and the `ind` writer emits only stems above
`height_min = 5 m` (`fwriteoutput_ind.c:84`, CLAUDE.md §3), while `a_fpc` sums **all** trees. Measured as
`(Σ fpc_ind, patch mean) / a_fpc` at 2010 (`>5m_frac`): `temperate_hainich` **0.96**,
`mediterranean_iberia` 0.95, `tropical_amazon` 1.02 — but `boreal_siberia` **0.71** and `semiarid_sahel`
**0.71**, i.e. those two cells carry ~29 % of their crown cover in stems F is never handed. **No F-vs-C FPC
ratio may be read against 1.0** — it must be read against this factor, and the probe now prints it per cell.

## 3b. Separating the canopy RECONSTRUCTION from F's GROWTH — the reconstruction is faithful

The 10-yr and even the year-1 ratios still mix two different things, because the annual output is written
*after* a year of F's own growth. Adding F's crown cover at **t = 0**, before any daily physics or
`annual_step!`, separates them exactly (probe PART 6, job **1718979**):

| cell | `t0` (F at t=0 / C `a_fpc` 2010) | `>5m_frac` | **`t0/>5m_frac`** | 2010 | → 2019 |
|---|---|---|---|---|---|
| `boreal_siberia` | 0.74 | 0.71 | **1.04** | 0.99 | **1.82** |
| `temperate_hainich` | 0.96 | 0.96 | **1.00** | 1.01 | 1.33 |
| `mediterranean_iberia` | 0.96 | 0.95 | **1.01** | 1.31 | 1.58 |
| `semiarid_sahel` | 0.71 | 0.71 | **1.00** | 0.68 | **0.47** |
| `tropical_amazon` | 1.02 | 1.02 | **1.00** | 0.93 | 1.10 |

**`t0/>5m_frac` = 1.00–1.04 in all five cells.** Given the exact stems it is handed, F reproduces their
crown cover to within 4 % at boreal and 0–1 % everywhere else. **F's canopy reconstruction is faithful and
is eliminated as a cause** — every remaining discrepancy is F's growth, which is a different fix and a
different file. This is the one unambiguously new positive result here.

### ⚠ but a `slow = nothing` arm has NO MORTALITY, so its monotone rise is partly expected

Under `slow = nothing` the fast core neither establishes nor kills trees: the only establishment branch in
`annual_step!` is **grass** (`fast.jl:272-295`, `n_est = 0` for a tree-only patch — the probe reports
`grass = 0` in all five cells), and mortality is line S's. The roster is fixed and individuals can only
grow. So *some* of the walk from 1.00 to 1.82 at boreal is the absence of the mortality the C applies every
year, not an F defect, and this arm **cannot** by itself convict F's growth.

Two things survive that caveat, and they are the findings:

- **`semiarid_sahel` shrinks 0.71 → 0.47 with no mortality acting at all.** Nothing in this arm can remove
  crown cover except F's own allocation, so this is unambiguously an F-side defect — and it is
  ADR 0052's dry-cell root-zone bias, now visible as a fourth independent symptom in the same cell.
- **The coupled arm, which DOES have demography, drifts almost as much.** Line S's ADR 0105 REPORT 5 (S
  active) measured F's `fpc` at **1.56×** over the window at boreal against the C's 0.90×, versus 1.65× here
  with no mortality at all. Mortality therefore accounts for only a small part of it, so the growth
  divergence is real — but **it must be quoted from the coupled arm, not from this one.**

## 4. What this does and does NOT change for line S's hand-over

ADR 0105 §5 handed line M an attribution: the coupled count residual is F's canopy diverging from the C's,
supported by 2019/2010 drift ratios (F's `fpc` 1.56× vs the C's 0.90× at boreal, 1.27× vs 1.00× at Hainich,
0.71× vs 1.23× at the Sahel). Those C figures are `a_fpc_stand` ratios.

**The attribution stands and the drift numbers barely move**, because a same-basis *ratio over time* mostly
cancels the difference in functional form. On the crown basis the C's own 2010→2019 change is **−10.9 %**
(boreal), −2.6 % (Hainich), −22.9 % (mediterranean), **+25.4 %** (Sahel), −11.0 % (Amazon), against F's
**+64.5 %**, +28.6 %, −7.0 %, −13.5 %, +4.7 %. F's canopy still grows where the C's shrinks at boreal and
shrinks where the C's grows at the Sahel. So:

- **the divergence-of-drift claim survives the basis correction** — it is a real F-side defect on M's paths;
- **the level claim inside it does not** — F's canopy is not uniformly sparse relative to the C's, it is
  too dense in three cells and too sparse in one, which changes what a fix has to do.

Both halves are now readable off one table (`fpc_tree` and `fpc_tree_crown` side by side in
`biome_slow_oracle_probe.jl` REPORT 5, and PART 3/6 of the F-side probe).

**Cross-checked by a second, independent harness (job 1718987).** The coupled S-side probe's REPORT 5, which
reads the annual table through its own reader, returns the C's 2019/2010 crown ratio as
**0.89 / 0.97 / 0.77 / 1.25 / 0.89** — the same digits the F-side probe's `Cdrift%` gives
(−10.9 / −2.6 / −22.9 / +25.4 / −11.0 %). Two readers, one table, agreeing, which is what licenses quoting
either. The same report shows why the basis matters *less* for a drift than for a level: `C_fpc` vs
`C_fpcBL` is 0.89/0.90 at boreal, 0.97/1.00 at Hainich and 1.25/1.23 at the Sahel — close — while diverging
at mediterranean (0.77 vs 0.67) and Amazon (0.89 vs 0.99). So a *ratio over time* is partly robust to the
substitution and a *level* is not, which is exactly why the level claim died and the drift claim did not.

## 5. Consequences

1. `test/testitems/references/M_fdiff_oracle_biomes{,_annual}.csv` gain `fpc_tree_crown`
   (+ `fpc_grass_crown` on the monthly table), appended last. **Every pre-existing column is
   byte-identical**, verified row-by-row against the pre-edit files, so no committed baseline moves and
   guardrail 4 is untouched. `M_fdiff_oracle_meta.json` gains `fpc_tree_crown_mean`,
   `fpc_grass_crown_mean` and `crown_over_stand_fpc`, and both `basis` strings now say which form they are.
2. **ADR 0053 finding 4 is withdrawn**; ADR 0053's other three basis corrections (grass removal via the
   id-419 output, the 25-patch ensemble, year-matched scoring) are unaffected and stand.
3. The open F-side item is **re-specified and narrowed, not closed.** What is eliminated: the canopy
   reconstruction (faithful to 0–4 %) and the "uniformly sparse canopy" reading. What remains: F's
   **growth** over-runs the C's in three cells and collapses in one, it is `src/fdiff.jl` /
   `src/components/fast.jl` (line M), and it is still unattributed to a term. The next measurement is
   named: score the growth divergence on the **coupled** arm (which has mortality) rather than the
   kernel-isolation arm, and check the Sahel first because it is the only cell this arm can convict.
4. Nothing in `src/` changed, so no gate-watched Julia path is touched and no baseline moves.

## 6. The rule this earns

**When a model emits two outputs whose names differ only by a qualifier, read both writers before picking
one — and if your own side implements a named expression, match the output that implements the *same
expression*, not the output with the closest name.** A one-line grep of the accumulation site
(`getoutput...(X) +=`) distinguishes them; the `outputvars.js` description does not, and neither does the
value range. Added to the `fdiff-validate` skill as a mandatory basis check alongside ADR 0053's four.

Corollary for reviewers: a comment asserting a basis is **CLEAN** deserves the same scrutiny as a number.
This one carried a correct C source citation next to the wrong file for five weeks.
