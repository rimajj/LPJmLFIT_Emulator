# The committed Hainich demo count DRF is trained on the retired PROXY features, while the copula beside it is on the REAL ones — one emulator, two conditioning bases

> **Status.** `accepted` as a decision + a measured defect report. Nothing is regenerated by this ADR: the fix
> moves a committed golden fixture, which is an integration point with line M (CLAUDE.md §9, guardrail 4), and
> doing it inside ADR 0031's population widening would make both before/after tables unreadable. The repo stays
> byte-identical and green in the meantime.

## What was measured

ADR 0031 §3 set a gate: regenerating the Hainich demo artifacts after the tree-PFT widening must be
byte-identical, because Hainich (cell 42490) contains only tree ids 1-5 + grass 8, so the widening cannot touch
it — "if they move, stop." They moved. `scripts/verify_hainich_demo_artifacts.sh` (job 1622105) reported
`drf_forest_hainich.drf` + `_meta.txt` modified, while `hainich_slow_oracle_{counts,traits}.csv` and
`recruit_copula_hainich.rcop` stayed byte-identical.

The DRF meta's golden feature rows name the cause. Against `colnames`
(`bm_inc_cell growth_eff water_stress soilmoist hmean hmax agb lai fpc age_mean n_prev …`), golden row 1:

| feature | committed `.drf` | regenerated | what the value is |
|---|---|---|---|
| `soilmoist` | **0.7** | 0.8600 | 0.7 is the retired *constant proxy* |
| `lai` | **21.22** | 2.7716 | 21 is the retired Σ-per-crown ind-LAI *proxy*; ~3 is the real C `LAI_STAND` cell-mean |
| `growth_eff` | **18.97** | 145.26 | = applied_npp / lai, so it follows its denominator |
| every other column | unchanged | unchanged | `bm_inc_cell`, `hmean`, `hmax`, `agb`, `fpc`, `age_mean`, `n_prev`, boundary — all bit-identical |

So the movement is exactly the **proxy → real** `soilmoist`/`lai` migration (slow-drf-pipeline step 0/1:
`build_swc_soilmoist_feature.py` from daily `swc`, `build_laistand_lai_feature.py` from C `LAI_STAND`), which
the builder adopted *after* this fixture was last written.

**The ADR-0031 edits are NOT the cause — proven, not argued.** `scripts/diagnose_slow_table_drift.py` (job
1622128) built the Hainich table twice, once with the builder at `git HEAD` and once with the working tree, under
identical settings: **all 15 columns and the target `y` agree with max|abs diff| = 0**, and `n_init`/`age0` are
identical. The widening is a no-op here (ids 1-5 only) and the `growth_eff` zero-lai guard is a no-op here
(seed1 has **zero** `lai == 0` tree-groups globally — `scripts/diagnose_lai0_growth_eff.py`, job 1621973). The
fixture would fail that gate under *any* edit.

**The sharp finding is not staleness but DISAGREEMENT.** The copula's own fallback conditioning row records its
basis, and it is the *other* one:

| committed fixture | last written | `growth_eff` | `soilmoist` | basis |
|---|---|---|---|---|
| `recruit_copula_hainich.rcop` | 2026-07-27, ADR 0025 (`95e272a3`) | 150.53 | 0.8539 | **REAL** |
| `drf_forest_hainich.drf` | 2026-07-23, ADR 0024 (`cdb352f2`) | 18.97 | 0.7 | **PROXY** |

A freshly built table gives `growth_eff` mean 151.9 / `soilmoist` mean 0.853 — i.e. the `.rcop` is on the
current, runtime-consistent basis and the `.drf` is not. The coupled `FluxDrivenSlowEmulator` loads **both at
once** (the DRF sets the count target, the copula samples recruit traits) and they share four conditioning
columns, so today's demo emulator is driven by two artifacts that disagree about what `growth_eff` and
`soilmoist` mean.

## Why it is a defect

- **It is an ADR-0023 train/inference shift, the exact class that ADR is about.** The runtime computes
  `soilmoist = sum(state.w)/length(state.w)` (`slow.jl:498`) and `lai = Σ leaf_c·sla·nind` (`slow.jl:489`), then
  `growth_eff = leaf_area > 0 ? applied_cell/leaf_area : 0` (`fast.jl:369`). Those produce the REAL-basis
  magnitudes (~0.85, ~3, ~150), not the proxy ones (0.7, ~21, ~19). The count DRF is therefore queried far
  outside its trained band on two of eleven head features at every step of the coupled loop.
- **The in-loop gates cannot see it, and that is documented behaviour, not bad luck.** The DRF leaf-clamps
  out-of-domain inputs (slow-drf-pipeline: "the DRF is fed OOD inputs and predicts nonsense while STILL
  conserving carbon — the error is masked"), so `slow_production_drf_tests.jl` still passes its
  "targets inside the training band" assertion and carbon still closes to ~1e-12. *(That clamping is the leading
  explanation for the green gates; it is inferred from the DRF's structure, not separately measured here.)*
- **No ADR ever retired the proxies for one artifact and not the other.** ADR 0023 §3 froze
  train/inference consistency; the proxy→real migration was a pipeline improvement that regenerated the
  copula (ADR 0025, same week) but never the older count DRF. Nothing recorded the resulting split basis.
- It survived because **nothing compared the two fixtures to each other**, and because the byte-identity gate
  it would have tripped did not exist until ADR 0031 §3 demanded one.

## Decision

1. **The REAL joined features are the correct basis** — they are what the runtime produces. `soilmoist` from
   daily `swc` (23-layer unweighted mean, matching `slow.jl:498`) and `lai` from C `LAI_STAND`, with the
   documented per-patch caveat. The proxies (`0.7`, Σ-per-crown) are retired and must not reappear.
2. **`drf_forest_hainich.drf` + `_meta.txt` are STALE and MUST be regenerated** — but as **milestone S1c**, its
   own deliberate change, NOT inside ADR 0031's widening. Regenerating a committed baseline is an integration
   point (CLAUDE.md §9) and it moves the drift thresholds in `slow_production_drf_tests.jl` and
   `slow_oracle_tests.jl`, which must be **re-measured and documented**, never widened silently
   (`residual-diagnosis`). Landing it together with the population change would leave two entangled causes for
   every moved number — precisely what ADR 0031 §3 forbids.
3. **Until S1c lands, every result read off the committed Hainich demo DRF carries the label "proxy-basis
   demo artifact".** It remains a valid *plumbing* fixture (the bitwise round-trip and conservation gates are
   basis-independent); it is not evidence of conditioning fidelity.
4. **The gate keeps a two-tier verdict.** `scripts/verify_hainich_demo_artifacts.sh` now runs
   `scripts/diagnose_slow_table_drift.py` as a control and distinguishes `STALE-FIXTURE` (exit 2 — fixtures
   moved but the edit is a no-op) from `FAIL` (exit 1 — the edit moved the table). A one-tier byte-identity gate
   against a possibly-stale fixture cannot tell those apart, which is why the first run of it was ambiguous.
5. **Fixtures that are regenerated together must be regenerated TOGETHER.** The count `.drf` and the recruit
   `.rcop` share four conditioning columns and are loaded by one emulator, so S1c regenerates both from the
   same table build and asserts their `growth_eff`/`soilmoist`/boundary bases agree. A future basis change does
   the same or it re-opens this defect.

## Consequences

- **The Hainich Gate-3 numbers may move**, including the `slow_oracle_tests.jl` quantile-RMSE drift alarm
  (documented ~0.31, with 0.39 observed vs a 0.45 threshold — `lines/S/STATE.md` S5). Direction is not
  predictable: the DRF will be *in*-domain for the first time, which should help, but the thresholds were tuned
  against the OOD-clamped behaviour. Re-measure, then re-state the alarm with its new basis.
- **The oracle CSVs and the `.rcop` are unaffected** (byte-identical through both the widening and this
  finding), so the trait-side single-cell evidence stands as measured.
- **No global number changes.** The global artifacts (`drf_forest_global_*`, `recruit_copula_global_*`) were
  built by `run_global_slow_*.sh` from tables produced by the current builder, i.e. already on the REAL basis;
  only the *committed single-cell demo* DRF is stale. ADR 0031's global re-derivation is therefore unblocked by
  this ADR and proceeds independently.
- **The runtime needs no change** — `fdiff`/`slow.jl` already compute the correct quantities. This is an
  artifact/table defect only, exactly like ADR 0031.

## Alternatives considered

- **Regenerate it now, inside the ADR-0031 widening.** Rejected: it entangles two causes in every moved
  Hainich number and silently moves golden thresholds mid-milestone. The whole point of ADR 0031 §3's gate was
  to keep the population change isolated.
- **Accept the proxy basis and re-freeze it as intended scope** ("the demo fixture is only plumbing"). Rejected:
  it leaves a live train/inference shift in the one artifact new sessions read first, and it contradicts ADR
  0023's load-bearing rule. It would also keep the DRF and the copula permanently disagreeing.
- **Delete the committed demo DRF and gate only on the global artifacts.** Rejected: the committed text fixture
  is what makes the `.drf` round-trip and the coupled in-loop tests runnable in CI with no `/p/tmp` access.
  Fix the basis; keep the fixture.
